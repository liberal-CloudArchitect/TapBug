# 信息调研报告：AI 驱动的多智能体网络安全检查团队

> 项目代号：**Hermes** — 由编排系统驱动、多专家智能体协作的全流程网络安全检测团队
> 调研日期：2026-07-05
> 适用场景：Bugcrowd / HackerOne 等**授权范围内**的漏洞挖掘、渗透测试与安全研究学习

---

## 0. 调研目标与方法

本次调研为"封装一个 Hermes 安全检查团队 skill"这一想法提供事实基础，围绕三条主线展开：

1. **开源生态**：GitHub 上漏洞挖掘 / 渗透测试 / AI 安全 Agent 的代表性开源项目；
2. **前沿技术**：当前较为领先的自动化检测、渗透与漏洞发现技术；
3. **协作范式**：多智能体（multi-agent）团队分工与协作的工程模式，以及渗透测试行业既有的团队方法论。

方法上采用网络检索 + 权威仓库/文档抓取，交叉验证。所有结论均附来源，见文末「参考来源」。

> ⚠️ **合规前置声明**：本报告及后续方案默认所有能力仅用于**已获授权**的目标（自建靶场、CTF、Bugcrowd/HackerOne 明确 scope 内资产）。任何针对未授权系统的使用都可能违反《计算机欺诈与滥用法》(CFAA) 及国内相关法律。合规不是附加项，而是本项目的第一约束（详见第 4 节）。

## 1. 开源项目与框架全景

当前 LLM 驱动的安全自动化生态大致可分为五层。理解这个分层，是设计 Hermes 团队时"造轮子还是站在肩膀上"的关键判断依据。

### 1.1 自主渗透 Agent 框架（本项目最直接的参考对象）

| 项目 | 架构特征 | 覆盖阶段 | 对本项目的启示 |
|------|----------|----------|----------------|
| **PentestGPT** (GreyDGL) | Human-in-the-loop 副驾驶、任务树规划；USENIX Security 2024 论文，学术验证最强 | 规划 + 执行协调 | "任务树 + 人在环"是可靠 baseline |
| **CAI** (Alias Robotics) | 生产级、模块化 Agent + 6 类 agentic Pattern，支持 300+ 模型，内置侦察/利用/提权工具，带 prompt-injection 护栏 | 侦察→利用→提权→横向 | 与 Hermes 目标最接近，协作范式可直接借鉴 |
| **Strix** | 图结构并行 Agent 工作流，多个专业角色"像真实黑客一样"协作 | 分布式 Web 测试 | 专业角色分工 + 并行的范本 |
| **PentestAgent** | 多智能体 + RAG + 分阶段规划 | 侦察→利用 | RAG 注入领域知识 |
| **VulnBot** | 多智能体三阶段规划策略 | 脆弱性评估 | 阶段化规划 |
| **Cochise** | 多智能体、AD 专精、层级式 | Active Directory | 垂直领域专精思路 |

| **PentAGI** | 全自主，内置 20+ 安全工具 | 综合测试 | 工具内置 vs 外接的权衡 |
| **hackingBuddyGPT** | LLM 驱动的安全测试框架，擅长 Linux 提权 | 后渗透 | 单点能力可作为专家 agent |
| **Nebula** | 侦察、笔记、漏洞分析助手 | 侦察 + 分析 | 轻量侦察助手 |

### 1.2 MCP 工具编排层（Agent ↔ 真实工具的桥梁）

- **HexStrike AI**：MCP server，让 Claude / GPT 等 AI agent **自主调用 150+ 安全工具**，含实时 CVE 监控、攻击链发现、AI exploit 生成；v6.0 已进入 Kali Linux 工具库。这是"让 LLM 直接指挥真实武器库"的代表。
  - ⚠️ **双刃剑警示**：Check Point 报告指出，该工具发布数小时内即被地下渠道用于 Citrix NetScaler 0-day 利用。这印证了 Hermes 必须内置 scope 校验与护栏，否则同样的能力会成为风险源。

### 1.3 经典侦察 / 扫描工具链（久经考验、Hermes 的"手脚"）

ProjectDiscovery 系列构成事实标准的自动化 recon 流水线：

- **Subfinder**：被动子域名枚举（证书透明日志、DNS 数据集、搜索引擎），不直接触碰目标；
- **Amass**：更深的 DNS 主动/被动测绘，常与 Subfinder 互补；
- **httpx**：快速探活，返回存活主机 + 服务器/标题/状态码；
- **Nuclei**：基于 YAML 模板的漏洞扫描引擎，覆盖数百种已知漏洞/错配/暴露；
- 辅助：**gau**（历史 URL）、**jaeles**、**Scan4All**。

典型链路：`subfinder → (amass) → httpx → nuclei`，把繁琐的"发现"阶段自动化，把精力留给"利用"阶段。这正是 Hermes 侦察类 agent 应封装的底层能力。

### 1.4 CTF 专用 Agent

D-CIPHER（Planner + Executors + Auto-prompter）、CTFAgent（有状态任务树 + 两阶段 RAG）、InterCode-CTF Agent（ReAct&Plan，95% 通过率）等。对学习阶段的靶场练习有直接价值。

### 1.5 评测基准（Benchmark，用于验证 Hermes 效果）

**XBOW**（104 个 Web 安全 CTF 任务）、**Cybench**（40 个专业级 CTF）、**NYU CTF Bench**（200 个 CSAW 挑战）、**AutoPenBench**、**CAIBench**（10000+ 实例）、**3CB**（对齐 MITRE ATT&CK）。这些为"如何证明 Hermes 有效"提供现成标尺。

## 2. 前沿检测与渗透技术趋势

### 2.1 Agent 推理范式：ReAct 成为事实标准
几乎所有框架（CAI、RapidPen、InterCode 等）都采用 **ReAct（Reasoning + Action）** 循环：模型交替进行"推理→调用工具→观察结果→再推理"。CAI 进一步把它与 6 类 kill-chain 工具（侦察、利用、提权、横向移动、数据外泄、C2）绑定。

### 2.2 工具接入的两条路线：MCP vs 直接工具调用
社区分为两派：
- **MCP 派**（HexStrike AI 等）：通过标准协议把工具暴露给任意 LLM，解耦、可复用；
- **直接工具调用派**（PentestGPT、CAI、Strix、AutoPentester）：在框架内直接封装函数调用，控制更强。

对 Claude Code 生态而言，MCP 是原生一等公民，**Hermes 宜以 MCP 作为工具接入主通道**。

### 2.3 检索增强与知识注入（RAG）
PentestAgent、CTFAgent 等用 RAG 注入 CVE、writeup、payload 知识库，缓解模型知识陈旧与幻觉问题。

### 2.4 自主化程度跃升（能力与风险同步上升）
- **Shannon** 号称在 XBOW 基准达 **96.15%**，结合源码分析自主找漏洞；
- **NeuroSploit** 3 路并行、覆盖 100 种漏洞类型；
- **闭环对抗**（ZERO-APT）与**数字孪生风险缓释利用**（Automation-Exploit）等学术方向，探索在"仿真副本"上先验证利用、再降低对真实系统的破坏。

### 2.5 反重复 / 长上下文治理
AutoPentester 用 repetition identifier 实现 90.5% 循环削减；TermiAgent 用 memory tree 跟踪状态。**长任务的状态管理与防打转**是自主 agent 的核心工程难点，Hermes 必须正面应对。

## 3. 多智能体协作范式

### 3.1 通用编排模式（四种基座 + 组合）
业界收敛出四种基础编排模式，真实系统多为**混合/可组合**：

1. **顺序（Sequential / Pipeline）**：阶段化流水线，一个阶段输出喂给下一个；
2. **并行（Parallel）**：多 agent 同时处理独立子任务；
3. **层级 / 主管（Hierarchical / Supervisor）**：协调者做任务分解，worker 专注执行——**当前企业部署的主导架构**；
4. **动态 / 群集（Swarm / Mesh）**：去中心化对等协作，动态自分配任务。

> Gartner：多智能体相关咨询量从 2024 Q1 到 2025 Q2 增长 **1445%**；预计 2026 年底 40% 企业应用将嵌入 AI agent。这是一个正在爆发的工程方向。

### 3.2 CAI 的 6 类 agentic Pattern（安全领域已落地的具体范式）
Swarm（去中心化）、Hierarchical（层级 handoff）、Chain-of-Thought（线性流水）、Auction-Based（竞价接任务）、Recursive（自我迭代精炼）、Parallelization（并行）。**Handoff（交接）**由规则/协商/竞价驱动，并强调 **HITL**（Ctrl+C 人类接管）。

### 3.3 Claude Code 原生的两种多智能体机制
调研 Claude Code 生态得到两条可直接落地的路径：

- **Subagents（子代理）**：主会话内的聚焦 worker，独立上下文、干完向主 agent 汇报。适合"快速、聚焦、报告式"的分工——**Hermes 的主力机制**。
- **Agent Teams（智能体团队，实验特性）**：多个 Claude Code 实例协作，一个当 team lead 协调、分派、综合，队友各自独立上下文、可直接互相通信。需在 settings 开启 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`。适合更重的并行协作。
- **Skills**：`~/.claude/skills/` 下的 markdown 指令文件，充当特定任务的聚焦系统提示——**Hermes 本体就应是一个 Skill**，内部编排 subagents。
- **Agent SDK 的 workflow**：当需要从脚本编排数十到数百个 agent 时，把编排移出对话。

### 3.4 结论：Hermes 的协作范式取向
**编排者-工人（Orchestrator-Worker）为主干 + 阶段化流水线（Pipeline）承载 PTES 流程 + 局部并行**。即：Hermes 作为 Supervisor 做阶段推进与任务分解，各专家 agent 作为 worker 在对应阶段执行，侦察等可并行的子任务用 Parallelization，关键节点保留 HITL。

## 4. 渗透测试方法论与团队角色（行业既有智慧）

### 4.1 阶段化方法论
- **PTES**（网络）与 **OWASP Testing Guide / Top 10**（Web）是两大结构化、可复用标准；
- 红队作战的五阶段：**规划 → 侦察 → 攻击模拟 → 报告 → 修复复盘**；细化含"授权与范围界定、威胁画像选择、被动侦察、主动侦察、初始访问"。

### 4.2 团队角色分工（Hermes 智能体分工的现实映射）
- **Red Team**：进攻方，需精通攻击、社工、物理绕过、对抗战术；
- **Blue Team**：防守方；
- **Purple Team**：红蓝协同。

Hermes 本质是把红队的阶段化角色，映射为一组专家 agent（详见方案文档）。

### 4.3 Bugcrowd 合规框架（第一约束的具体条款）
- **Engagement Brief / Scope**：明确目的、范围与细则；应用显式 scope，而非模糊措辞；
- **VRT（Vulnerability Rating Taxonomy）**：技术影响分级的开源标准，Hermes 报告应直接对齐；
- **Rules of Engagement + Safe Harbor**：善意研究不追责；研究者应**仅做证明影响所需的最小 PoC**，不外泄数据、不建立命令行驻留、不越权扩大访问；
- **Coordinated Disclosure**：默认协同披露，修复后经双方同意方可公开。

> 这些条款不只是"外部规则"，它们应当被**编码进 Hermes 的护栏与工作流**（scope 校验、最小 PoC 原则、禁止外泄、自动生成对齐 VRT 的报告）。

## 5. 对本项目的核心启示

1. **不重复造轮子**：侦察/扫描用成熟工具链（ProjectDiscovery 系列），通过 MCP（HexStrike 式）接入；Hermes 的增量价值在**编排、专业分工、推理与报告**，而非底层扫描器。
2. **协作范式已有成熟答案**：Orchestrator-Worker + 阶段流水线 + 局部并行 + HITL，且 CAI/Strix 已在安全领域验证。
3. **Claude Code 是天然载体**：Skill（本体）+ Subagents（专家）+ MCP（工具）+ 记忆文件（知识沉淀）四件套齐备，无需从零搭框架。
4. **合规与护栏是设计核心而非补丁**：HexStrike 被滥用的教训 + Bugcrowd 条款，要求 scope 校验、最小 PoC、防外泄、可审计从第一天就内建。
5. **可验证**：用 XBOW/Cybench 等 benchmark 与自建靶场，为"想法是否可行/有效"提供客观标尺。
