# 可行性研究与实施方案：Hermes 安全检查团队

> 基于 `01-信息调研报告.md`（生态事实）与 `02-需求分析报告.md`（第一性拆解）产出的落地方案。
> 日期：2026-07-05

---

## 1. 可行性研究

### 1.1 技术可行性 — ✅ 高
| 支撑点 | 结论 |
|--------|------|
| 编排机制 | Claude Code 原生 **Skill + Subagents** 直接支持"编排者-工人"模式，无需自建框架 |
| 工具接入 | **MCP** 是原生一等公民；HexStrike AI（150+ 工具）等现成 MCP server 可直接接入侦察/扫描能力 |
| 协作范式 | Orchestrator-Worker + 阶段流水线 + 局部并行，已被 CAI/Strix 在安全领域验证 |
| 知识沉淀 | Claude Code 记忆文件机制天然承载 A8 |
| 参考实现 | PentestGPT（任务树+HITL）、CAI（6 类 pattern + 护栏）提供成熟蓝图 |

**判断**：核心能力全部有现成机制或成熟先例，Hermes 的工作是"编排 + 特化 + 护栏 + 报告"的集成创新，而非底层突破。技术风险低。

### 1.2 资源可行性 — ✅ 中高
- 载体是 Markdown（SKILL.md + agent 定义），无需搭建服务；
- 底层工具用开源（ProjectDiscovery 系列 / Nuclei）或现成 MCP，无自研扫描器成本；
- 主要成本是 LLM 调用与靶场环境，可通过并行度/预算护栏控制。

### 1.3 合规可行性 — ⚠️ 可行但为第一约束
- Bugcrowd 提供 Safe Harbor，善意研究有法律缓冲；
- 但 HexStrike 被地下渠道快速滥用的教训表明：**能力越强，护栏越必须内建**；
- 结论：合规可行的前提是 scope 校验、最小 PoC、禁外泄/持久化、可审计**从架构第一天就编码进流程**，而非事后补。

### 1.4 风险总览（详见第 6 节）
主要风险：越权/合规、模型幻觉误报、高危动作失控、成本失控、长任务打转。均有对应缓解，无致命阻断项。

> **总体结论**：想法**可行**。推荐以 Claude Code Skill 为载体，分阶段从 MVP 演进，合规护栏与 HITL 作为不可裁剪的核心。

**分层职责**：
- **编排层**：唯一持有全局状态与阶段控制权，负责 A1(部分)、A8、报告汇总；
- **专家层**：各自负责一段原子能力，独立上下文；
- **工具层**：通过 MCP 暴露真实安全工具；
- **存储层**：scope、发现、知识、审计日志落盘，支撑可审计与知识复利。

## 3. Agent 角色定义

> 每个专家对应 `02` 报告中拆解的原子能力。角色即 subagent 定义文件（`agents/*.md`）。

| Agent | 对应原子能力 | 核心职责 | 关键工具 | 风险等级 |
|-------|-------------|----------|----------|----------|
| **Hermes 编排器** | A1(部分)/A2-A8 调度 | 阶段推进、任务分解、handoff、状态与记忆、报告汇总 | — | — |
| **合规守门人 Gatekeeper** | A1 | 全程校验目标∈scope，拦截越界/危险动作，最小 PoC 原则守护 | scope 校验 | 否决权 |
| **侦察官 Recon** | A2 | 被动/主动信息收集：子域、资产、指纹、历史 URL | subfinder, amass, httpx, gau | 低 |
| **攻击面测绘 Mapper** | A3 | 结构化资产→端口/服务/路由/参数/认证入口清单 | nmap, httpx, katana | 低 |
| **Web 漏洞专家** | A4 | OWASP Top10：注入/XSS/SSRF/文件上传等识别 | nuclei, 自定义探测 | 中 |
| **认证授权专家** | A4 | IDOR、权限绕过、会话、越权逻辑缺陷 | 自定义 | 中 |
| **API 专家** | A4 | REST/GraphQL 参数滥用、鉴权缺失、批量分配 | 自定义 | 中 |
| **基础设施专家** | A4 | 错配、暴露服务、子域接管、CVE 匹配 | nuclei, CVE 匹配 | 中 |
| **利用验证 Exploitation** | A5/A6 | 构造**最小 PoC**验证可利用性，评估影响；**强制 HITL** | 受限执行 | 高（HITL） |
| **报告官 Reporter** | A6/A7 | 生成对齐 VRT 的发现：复现/证据/影响/修复/分级 | 报告模板 | 低 |

> 学习阶段可先落地精简版：**Hermes + 守门人 + 侦察官 + 攻击面测绘 + Web 漏洞专家 + 利用验证 + 报告官**（7 个），其余专家后续增量加入（NFR3）。

## 4. 协作流程（PTES 阶段 → agent handoff）

采用**阶段化流水线为主干，阶段内局部并行，关键节点 HITL**：

```
[阶段0 授权]  Hermes 载入 scope → 守门人确认边界 → 无授权则终止
     │
[阶段1 侦察]  Hermes 并行分派 Recon（多子域/资产同时）→ 汇总资产图
     │        ↳ 守门人对每个新发现资产做 scope 复核
[阶段2 测绘]  Mapper 结构化攻击面 → 输出入口清单
     │
[阶段3 识别]  并行分派 Web/认证/API/基础设施 专家 → 各自产出候选发现
     │        ↳ 去重、交叉校验
[阶段4 验证]  逐条候选 → 利用验证专家构造最小 PoC
     │        ⏸ HITL：高危动作执行前暂停征询人类
[阶段5 报告]  Reporter 汇总 → 对齐 VRT 生成发现 → Hermes 复核
     │
[阶段6 沉淀]  Hermes 把有效 payload/方法/教训写回 knowledge/
```

**协作机制要点**：
- **Handoff**：Hermes 用结构化交接（上一阶段产物作为下一 agent 输入），对应调研中的 hierarchical pattern；
- **并行**：阶段1/3 用 Parallelization（subagents 并发），压缩时间；
- **防打转**：借鉴 AutoPentester 的 repetition identifier 思路，Hermes 检测重复动作并强制推进或求助；
- **状态**：全局状态由 Hermes 持有（TermiAgent memory-tree 思路），专家无状态、纯函数式回传。

## 5. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 载体 | **Claude Code Skill**（`SKILL.md`） | 原生、可移植、即装即用 |
| 专家 | **Subagents**（`agents/*.md`） | 独立上下文、报告式回传，契合 orchestrator-worker |
| 重并行（可选） | Agent Teams（实验特性） | 需要真并行多实例时启用 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` |
| 工具接入 | **MCP**（HexStrike / 自建 wrapper） | Claude 原生协议，解耦、可复用 150+ 工具 |
| 推理范式 | **ReAct** | 行业事实标准，工具循环稳定 |
| 知识注入(可选) | 轻量 RAG（knowledge/ 目录检索） | 缓解知识陈旧与幻觉 |
| 护栏 | scope 校验 + 危险命令拦截 + prompt-injection 防护 | 借鉴 CAI guardrails |
| 报告标准 | Bugcrowd **VRT** + CVSS | 直接对齐提交 |
| 评测 | XBOW / Cybench / 自建靶场 | 客观验证 |

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| **越权/合规** | 法律责任 | 守门人一票否决 + 全程 scope 校验 + 最小 PoC 原则 + 禁外泄/持久化，编码进流程 |
| **高危动作失控** | 破坏可用性 | 利用阶段强制 HITL；禁 DoS/破坏性 payload；受限执行环境 |
| **模型幻觉/误报** | 报告不可信 | 验证优于猜测（必须有 PoC 证据）+ 报告官/守门人交叉复核 + RAG |
| **长任务打转** | 成本/时间失控 | 重复检测 + 阶段预算护栏 + 求助 HITL |
| **成本失控** | 费用 | 并行度上限、模型分层（侦察用轻模型、推理用强模型）、单任务预算 |
| **工具滥用（HexStrike 式）** | 能力外溢 | 仅授权 scope 内启用；审计日志；危险命令白名单 |
| **上下文污染** | 质量下降 | subagent 上下文隔离（第一性收益之一） |

## 7. 实施路线图

### Phase 0 — 骨架与护栏（先做，1 步到可用）
- 建 `SKILL.md`、`agents/` 目录、`scope.md` 模板、审计日志约定；
- 先实现**守门人 + Hermes 编排 + 报告官** 的最小闭环（即使侦察靠手动喂数据）；
- ✅ 里程碑：能对一个假想 scope 走完"授权校验→占位流程→VRT 格式报告"，护栏生效。

### Phase 1 — MVP 全流程（侦察→报告打通）
- 接入 MCP 侦察工具（subfinder/httpx/nuclei）；
- 落地 侦察官 + 攻击面测绘 + Web 漏洞专家 + 利用验证(HITL)；
- ✅ 里程碑：在**自建靶场**上跑通端到端，产出可复现发现。

### Phase 2 — 团队扩展与并行
- 增补 认证授权 / API / 基础设施 专家；
- 阶段1/3 并行调度；防打转机制；
- ✅ 里程碑：多资产并行，新增专家仅需加文件（验证 NFR3）。

### Phase 3 — 知识复利与自评
- A8 知识沉淀写回 `knowledge/`，跨任务复用；轻量 RAG；
- 接 XBOW/Cybench 或自建题库做效果基线；
- ✅ 里程碑：有量化的通过率/发现质量指标，形成迭代闭环。

## 9. 成功指标

| 维度 | 指标 |
|------|------|
| 合规 | 越界请求 100% 被拦截；高危动作 100% 触发 HITL |
| 完整性 | 端到端跑通率（阶段0→6）|
| 质量 | 发现的可复现率、误报率、VRT 分级准确率 |
| 效率 | 单任务耗时 / 成本；并行带来的加速比 |
| 可扩展 | 新增专家 agent 的改动范围（应仅限新增文件 + 注册）|
| 效果基线 | XBOW/自建靶场通过率（Phase 3）|

## 10. 下一步建议

1. **确认 scope 与靶场**：先准备一个自建靶场（如 DVWA/靶机）或 Bugcrowd 授权 scope，作为 Phase 1 验证目标；
2. **从 Phase 0 骨架起步**：先把护栏 + 编排 + 报告闭环立起来，再逐步接工具与专家——护栏先行是本方案的核心原则；
3. **用 skill-creator 落地**：可用 Claude Code 的 `skill-creator` skill 生成 `SKILL.md` 与 agent 骨架，把本方案第 8 节结构实体化。
