## 0. 评审方法

对每份文档提三个问题：
1. **可落地性**：据此能否直接写出代码/配置，还是停留在意图层？
2. **自洽性**：文档内部及三份之间是否存在自相矛盾？
3. **威胁自审**：文档自己提出的风险（尤其 prompt injection、越权），其提出的缓解是否真的能挡住？

评审结论用严重度标注：🔴 阻断 Phase 0（必须先解决）· 🟠 影响 MVP 质量（Phase 0/1 内解决）· 🟡 优化项（可延后）。

## 2. 🔴 核心矛盾：合规护栏的"执行层"缺失（贯穿 01/02/03）

**问题**：三份文档反复强调"护栏必须**编码进流程**、从第一天内建"（`01`§4.3、`02`NFR1/NFR2、`03`§1.3/§6），并且**自己**引用了 HexStrike 被 prompt injection / 地下滥用的教训。但在架构里，scope 校验与危险命令拦截被指派给 **合规守门人（Gatekeeper）agent** —— 而 agent 本质是一个 LLM，**恰恰可被 prompt injection 绕过**。

> 即：文档用来防御风险 X 的手段，本身可被风险 X 攻破。这是自相矛盾。

**根因**：`01` 调研 Claude Code 多智能体机制时，只覆盖了 Subagents / Agent Teams / Skills / Agent SDK，**遗漏了 Hooks（PreToolUse / PostToolUse）** —— 而 Hooks 才是 Claude Code 里唯一**不经过 LLM、确定性执行**的拦截原语。

**处置（Phase 0 内解决）**：护栏分两层——
- **硬护栏（确定性，不可被 prompt 绕过）**：用 **PreToolUse Hook**（`hooks/guardrail.py`）拦截 Bash/工具调用，做 scope 匹配、危险命令黑名单、破坏性 flag 拦截，命中即 `deny`。这是合规的**地基**。
- **软护栏（语义，LLM 层）**：Gatekeeper agent 负责需要语义理解的判断（最小 PoC 原则、业务影响、这个动作"是否有必要"）。

Gatekeeper 从"唯一防线"降级为"第二层语义复核"，硬拦截交给 hook。**这一改动是本次评审最重要的产出。**

## 4. 补充规格 A：HITL 显式触发清单（解决 G2.5）

以下动作**执行前必须暂停征询人类**（其余可自动推进）：

1. 任何**主动向目标发送可能改变状态**的请求（POST/PUT/DELETE、写操作、上传）；
2. 任何**利用类 PoC** 的实际投递（即便只读取，只要目的是"证明可利用"）；
3. **认证/爆破/枚举**中可能触发账户锁定或告警的动作；
4. 触碰**新发现的、尚未经 scope 复核**的资产；
5. 任何被 hook 标记为 `ask`（灰名单）的命令；
6. 单任务**预算/时长即将超阈值**时的"是否继续"。

纯被动侦察、只读 GET、本地分析、报告生成 **不** 触发 HITL。

## 7. 命名与身份澄清（解决 G3.5）

- **Hermes**：编排系统/团队人格与方法论层（"谁在指挥、按什么流程"）。信使之神，负责传递与协调 —— 对应 Orchestrator。
- **Excavator（挖掘机）**：运行时与工具层的代号，即本项目的 **Python 环境名 `excavator`** 与所有可执行脚本/hook/MCP wrapper 所在。"挖掘"漏洞的执行底盘。
- **hermes-security-team**：Claude Code 中该 Skill 的 `name`（技术标识符）。

三者关系：*Hermes 指挥，Excavator 执行，hermes-security-team 是它在 Claude Code 里的注册名。*

> 现行修正：PRD 1.0 将 Hermes 定义为产品/方法论和编排控制平面，不是具体模型/provider；`Excavator` 仅保留为历史开发环境代号，不再是产品安装前提或安全边界。

## 8. 评审结论

三份文档**方向与骨架均成立**，可作为项目基座；但存在 **7 个 🔴 阻断项**（集中在：护栏执行层、handoff 契约、scope/状态/审计 schema、skill 安装位置、Phase 0 DoD），若不补齐，Phase 0 会建在"意图"而非"规格"之上。

本报告已为每个 🔴 给出**可落地处置**，其中最关键的是**引入 Hooks 作为确定性硬护栏**，修复了原方案"用可被绕过的 LLM 去防越权"的自相矛盾。

> **裁决**：补齐本报告的增补规格（§2、§4、§6、§7 + 各 schema）后，文档体系达到"全面完善"，**批准进入 Phase 0**。以下 Phase 0 交付物即按本报告的处置实现。
