## 1. 产品定义

Hermes 是一个面向明确授权目标的、受策略治理的自适应多智能体安全评估系统。它通过两条相互衔接的主流程产生价值：

1. **安全评估闭环**：授权确认 → 侦察 → 测绘 → 多领域分析 → 候选发现 → 审批 → 最小验证 → 人工复核 → 报告。
2. **能力学习闭环**：识别知识/工具缺口 → 研究可信资料 → 形成能力规格 → 生成候选 Wheel → 离线和沙箱验证 → 人工签名审批 → 受控复用 → 效果反馈与撤销。

历史 V1 localhost 教学 fixture 保留为只读审计基线。现行 V2 领域契约和
EvidenceArtifact V2 已通过真实 Docker + Hermes ACP accepted/reject E2E 和 7 类 strict tamper
验收。其上新增的 V3 协作链也已在 localhost Phase 4 fixture 验收：Web/API/Authz/Infra 四路
并行、确定性 fan-in/去重、独立环形交叉复核、两批审批、动作/预算 ledger、补偿与双阶段报告
preflight 均已运行。R2.5 的首个 passive parser 也已使用两个真实 ACP/Docker 角色、签名 Wheel
registry 与零网络 Docker sandbox 完成独立 child continuation。上述结论都只适用于固定教学靶场；
真实资产 profile、任意漏洞族、V3 原地恢复式 Wheel 学习和独立质量 benchmark 尚未验收。

## 4. 目标、用户与边界

### 4.1 目标用户

- 在自建靶场中学习漏洞挖掘和渗透测试的安全学习者。
- 依据明确 RoE 在 Bugcrowd 等平台上开展良性研究的研究员。
- 审查评估计划、主动动作、证据和 Wheel 的操作员/审批人。

### 4.2 产品目标

- 在显式授权边界内生成可追溯、可复核的安全评估结果。
- 通过专家上下文隔离、并行、结构化交接和交叉复核提高评估质量。
- 使未知问题能够转化为可溯源、可验证、可撤销的低风险能力包。
- 将“格式对齐 VRT”、“内部证据达到 validated”和“可提交到具体平台”分为三个不同等级。

### 4.3 当前支持范围

- 显式 host/wildcard/CIDR、scheme、port、DNS、profile 和预算限制的 scope 快照。
- 默认零网络计划、run-scoped artifacts、审计、审批令牌和证据契约。
- Candidate 与 ValidatedFinding 分离；正式报告只消费符合契约的发现。
- 七个 V2 领域模型、类型化 ContractEnvelope、EvidenceStore V2、PromotionService、
  CoverageReport 和统一 ReportPreflightVerifier。
- 受治理知识、Wheel 生成、验证和注册的单元/契约能力，以及 local-lab 上固定
  `line_kv_parser/v1` 的真实 ACP/Docker 被动解析闭环；它只输出独立 child continuation observation。
- localhost 教学 fixture 上的六角色 Hermes ACP + Docker 最小纵向闭环；验收边界见 9.1 节。
- localhost Phase 4 fixture 上的九角色 V3 协作闭环：四个评估分支并行、候选去重、环形交叉
  复核、只读/状态变更两批审批、受 ledger 约束的最小验证和补偿；验收边界见 9.2 节。
- **V4 检测与报告（受限 local-lab，主路径已有真实工件，未完整产品验收）**：八类固定候选、TLS/header/Cookie
  posture、局部 OpenAPI projection、320-case 冻结质量数据集与 preflight 重算；主路径真实 ACP+Docker 工件为
  `artifacts/phase5-e2e/20260801T075539Z-…`（accepted 28 evidence/8 finding、readonly reject、六类 tamper
  blocked、幂等 recovery）。**仍未完成**：完整韧性矩阵（mutation reject/分支失败/crash 不重放/cleanup 失败/
  完整 tamper-matrix 于单一 `--scenario all` 权威根）、CI 强制与独立 benchmark；不得据此声称真实资产可用或真实发现率已证明。
- **批准后的最小主动 PoC** 只在固定 localhost teaching fixture 上支持：每个动作必须已存在于
  签名 approval batch，父运行时以一次性 consumption 通过 Gateway 执行正/反对照；对真实资产不
  提供这一承诺或默认授权。
- 当前验收的具体模型运行时为 `HermesAcpProvider`：父进程通过受限 ACP bridge 调用 Hermes Agent
  `0.16.0` / ACP protocol 1，并使用配置中的模型名；role container 不持有 provider 凭据、网络或
  工具权限。这个兼容基线不是“任意 Hermes CLI/provider 都已验收”的声明。
- `extensions/hermes_ctf_lab` 是独立教学扩展，不属于主包交付、报告或真实 engagement 控制面。
- Wheel 是 v3 后续扩展的独立受治理面，而不是 V2/V3 安全评估闭环的前置依赖；当前只验收其
  `passive_parser` child continuation，不能用它扩大评估权限。

### 4.4 当前不可声称的能力

- 已验收的“真实多智能体并行”声明只适用于固定 localhost Phase 4 teaching fixture；它不代表
  多资产调度、任意路由、任意漏洞类型、真实身份系统或完整专家覆盖。
- 本地靶场 E2E 通过不等于真实资产 profile 获准；在独立的真实域名治理验收前不得宣称可用于 Bugcrowd 资产。
- 未经平台规则和人工复核时，不得把内部 validated 称为“必然可提交”。

### 4.5 交付等级不得混用

| 等级 | 含义 | 当前系统能证明什么 | 不能证明什么 |
|---|---|---|---|
| VRT 格式对齐 | 报告字段和严重度建议可与 VRT/CVSS 表达形式对齐 | 本地 fixture 报告可生成摘要、影响、复现、证据和修复建议 | 不代表对应平台会接受分类或严重度 |
| 内部 `validated` | 父运行时已从当前 run 的批准、consumption、证据和人工签名重验 finding | 固定 local-lab 证据链中的内部可复核结论 | 不代表真实资产影响、平台 policy 合规或赏金资格 |
| 平台可实际提交 | 研究员按当期项目 RoE、测试条件和披露规则人工确认后提交 | 系统只可提供脱敏草稿和审计材料 | 只能由平台和人工判断，绝不能由 Hermes 自动宣称 |

### 4.6 永久非目标

- 未授权测试、DoS、数据外泄、持久化、检测规避和对真实凭据的攻击。
- 在主包中提供夺旗、RCE/pwn/crypto、爆破或任意利用代码生成。
- 让 agent、网页、模型输出、环境变量或 Wheel 改变 scope、审批和策略。

## 5. 不可变安全原则

1. 所有 HTTP、DNS、命令和凭据使用必须经父运行时 Gateway；hook 仅是外围辅助（护栏判定规则见 `docs/17-硬护栏行为规范.md`）。
2. 任何超出冻结 scope、自动化许可、预算或审批的动作在连接建立前拒绝。
3. 认证请求、状态变更、注入探针、外部 CLI 和主动验证需要与 run/scope/action/target/TTL/预算绑定的审批。
4. 模型结论、模板命中和 Wheel 输出都是候选，不能自行升级为漏洞。
5. 正式 finding 必须绑定当前 run/scope、已消费审批、脱敏证据和可验证的人工复核。
6. 未签名、未审批、过期、被篡改、quarantined 或 revoked 的 Wheel 不得被选择或执行。
7. V1 run/evidence 只读；不得静默升级、恢复、复核、晋升或重新生成正式报告。
8. 模型对响应语义的声明不是证据；父运行时/preflight 必须从 hash-bound analysis
   和 manifest 重算安全相关 header、Link、状态码和 body 差分。

## 6. 功能需求

### 6.1 v2 控制面

- **GOV-01 授权与 Scope**：录入并冻结 RoE，严格校验 host/wildcard/CIDR、scheme、port、DNS、profile 和自动化许可。
- **GOV-02 唯一工具网关**：网络、DNS、命令和凭据使用只能通过受策略约束的 Gateway。
- **GOV-03 HITL 审批**：高风险动作支持 challenge、明确批准/拒绝、暂停、过期和恢复，审批人与执行者分离。
- **GOV-04 运行隔离与可恢复**：每次评估使用不可变 scope 快照和独立 artifacts，支持经 hash 校验的安全恢复。
- **GOV-05 证据和报告边界**：Candidate、blocked、inconclusive 与 ValidatedFinding 分离；晋升只由父运行时执行，报告前必须从真实 canonical artifacts 逐项重验。
- **GOV-06 审计与数据治理**：记录 agent/model/tool/approval/Wheel 生命周期；证据保存限长、按 MIME/字段脱敏的 analysis 副本和可选 AES-GCM raw 副本，并绑定 run/scope/task/action/plan/approval/consumption。

### 6.2 v1 多专家评估

- **AGT-01 Hermes/provider 适配**：Hermes 通过受控 adapter 启动真实模型驱动的独立专家。
- **AGT-02 结构化角色契约**：Gatekeeper、Recon、Mapper、Web、API、Authz、Infra、Verifier 和 Reporter 各有版本化输入/输出、权限、预算和失败语义。
- **AGT-03 端到端阶段编排**：完成授权、侦察、测绘、识别、审批验证、复核和报告。
- **AGT-04 并行和协作**：独立资产及 Web/API/Authz/Infra 分支可并行，支持失败隔离、去重、交叉复核和 coverage 汇总。
- **AGT-05 预算和防打转**：统计模型/工具调用、时间、请求和费用，检测重复动作并停止无效循环。

### 6.3 v3 知识与 Wheel

- **CAP-01 知识缺口识别**：将未知现象形成与 run/task/evidence 绑定的 ProblemCard，支持去重和人工定义。
- **CAP-02 可溯源研究**：Researcher 只经 Gateway 访问 allowlist 来源，保存时间、版本、许可证、内容 hash、适用条件和风险标记。
- **CAP-03 能力规格与生成**：先生成 CapabilitySpec，再用版本化、确定性模板生成低风险 Wheel、测试、SBOM 和锁文件。
- **CAP-04 静态与反例验证**：禁止未声明网络、命令、动态执行和越界文件操作，必须附正例、反例和 golden fixture。
- **CAP-05 真实沙箱验证**：候选 Wheel 只在无网、非 root、只读、资源受限的 digest-pinned 容器中验证和执行。
- **CAP-06 注册与生命周期**：Wheel 经独立人工审批和签名后才能 active，支持过期、quarantine、revoke 和来源撤回。
- **CAP-07 安全评估恢复**：原评估可因知识缺口暂停，只在受批 Wheel 可用后恢复，并将实际效果反馈到 registry。

### 6.4 检测与交付

- **DET-01 攻击面发现**：对资产、路由、参数、认证入口、服务和配置形成有 coverage 的结构化清单。
- **DET-02 多领域候选分析**：Web/API/Authz/Infra 专家产生带反例和所需证据的 Candidate，不因单一模板命中升级。
- **DET-03 最小主动验证**：在 RoE 允许且逐次审批时，Verifier 使用正反对照和最小请求证明或否定候选；这是未来目标，不是当前真实资产承诺。
- **DET-04 平台对齐报告**：输出摘要、影响、前置条件、复现步骤、脱敏证据、修复建议、VRT/CVSS 及覆盖/未测项。
- **DET-05 质量评估**：用独立 ground truth 分别计量 candidate recall、validated precision、误报、漏报、成本、时延和阻断次数。

## 7. 非功能需求

- **NFR-01 安全与合规**：默认拒绝，策略不可由模型或扩展放宽。
- **NFR-02 可审计性**：所有关键决策和输出都可关联到主体、run、scope、action、审批和证据。
- **NFR-03 可扩展性**：新角色或能力通过契约、manifest 和注册加入，不放宽核心策略。
- **NFR-04 可观测性**：提供阶段、任务、阻塞、成本、请求、时延和 coverage 状态。
- **NFR-05 可恢复性**：中断、超时或缺少审批时 fail-closed，且可从验证过的事件链恢复。
- **NFR-06 可重复性**：依赖、镜像、prompt、manifest、scope、数据集和输出均有版本/hash。
- **NFR-07 成本可控**：可设置模型、任务、请求、并发、时间和费用预算。
- **NFR-08 可移植性**：核心契约不绑定单一 provider；Claude/Codex/其他 provider 由 adapter 接入并经同一验收套件。

## 9. 产品级验收场景

### 9.1 多专家评估 E2E

当前 localhost 固定链产品级完成门已关闭：真实受信角色完成 Gatekeeper → Recon → Mapper →
单一 Web Candidate → 暂停审批 → Verifier 正反对照 → 人工签名 → 报告。权威根为
`artifacts/phase3-authoritative-e2e/20260714T044246Z-phase2-fe73e3b1b378/`。Accepted
`232c6b5c-9e6d-4933-830c-d10be1f7a5b6` 证明六角色/容器/ACP session、3 份 HTTP evidence +
analysis、2 份 consumption、candidate 2/control 1 和 completed 报告链；rejected
`f3650961-a210-4c2a-bfb0-d88c613f32c8` 仅有 Recon evidence、`requests_used=1` 并终止为
rejected。strict tamper 7/7 阻断且 `formal_reports_created=0`。

父运行时/preflight 的现行实现从受 hash 保护的 `analysis.json` 重算 Recon `Link`、candidate
缺 XCTO、control=`nosniff`、双方同 200/同 body。Provider metadata 必须提供正整数
`prompt_attempts`，且明确拒绝布尔值；Coverage 以其求和。实测 `model_calls=6`，其中 Recon
schema repair=2，其余 Reporter 前角色各 1；`elapsed_ms=221031`，`cost_microusd=null` 表示
provider 未提供成本；steps 2/2、finding 1。三份 analysis 为 579/592/592 bytes。最终代码门为
该次 2026-07-14 验收的代码门为 173 passed / 1 skip，唯一 skip 是 R2.5 Wheel Docker sandbox；Ruff lint/format、strict mypy、
registry validate、wheel build 和 pinned transport 通过，E2E 后无遗留容器。
V1 public `start`/`resume` 仍在启动任何角色前返回 `legacy_run_read_only`。

角色进程和 16 个独立 ACP session：Gatekeeper/Recon/Mapper（3）→ 四路 assessment（4）→ 四个
独立 cross-review（4）→ 四个 verifier（4）→ Reporter（1）。它在 15 请求预算内产生 15 份
EvidenceArtifact、14 次审批 consumption、4 个正式 finding，最终 `completed`；cleanup state 为
`restored`，验收后无遗留容器。该闭环还保存 SignedReviewBatch、Reporter launch/ack/write receipts
和 hash-bound report。固定候选仅为 XCTO、GraphQL 未授权状态变更、权限提升和 debug endpoint；
Web 与 Infra 的重复 XCTO 原始候选由父运行时去重为一个规范候选。

另有真实 V3 Docker + ACP 变体：Web+Infra 动态子集为 10 task/5 请求/2 finding 且 API/Authz
不启动；mutation 拒绝为 5 请求/2 finding；readonly 拒绝为 11 请求/2 finding 且 cleanup restored；
两批均拒绝仅保留 Recon 1 请求、0 consumption 与 0 正式报告。完整证据见 `docs/12`。

P4-Resilience 还已用真实 Docker + ACP 覆盖 API 单分支失败隔离、cleanup-only 恢复、mutation
已提交后的 SIGKILL 不重放和 12 类篡改的 fresh-preflight 拒绝。它们不授予真实资产权限，也不证明
所有其他失败/超时组合已枚举完成；其余组合继续由 V3 契约和 fail-closed 回归覆盖。

### 9.3 未知问题/Wheel E2E

当前已验收的最小 R2.5 链为：冻结 V3 Evidence 的脱敏 analysis + 操作员观察 → Researcher 只读
归档资料 → Capability Planner 受父运行时样例 schema 约束 → 固定 parser spec/Wheel/正反例 →
真实 Docker 验证 → 独立人工签名 → registry active → 新的 child continuation 解析冻结输入并输出
结构化 observation。它不恢复 Mapper、不改写父 V3 run、不生成 endpoint/finding/报告；篡改、误报、
sandbox 异常或来源撤回后必须 quarantine/revoke，不能再被选择。
