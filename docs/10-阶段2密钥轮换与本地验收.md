# 阶段 2：密钥轮换与本地验收

状态：实施手册。2026-07-13 固定 localhost 最小纵向闭环已通过真实 Hermes ACP 与 Docker E2E；本手册同时保留复跑和密钥轮换步骤。

## 密钥职责

Publisher、Approver、Reviewer 必须使用三个不同的 Ed25519 key ID。私钥不得进入仓库或
`runs/`，权限必须为 `0600`；配置和运行产物只保存公钥、key ID、签名与哈希。

```bash
hermes-security keys generate --usage publisher --out /secure/hermes/publisher.pem
hermes-security keys generate --usage approver --out /secure/hermes/approver.pem
hermes-security keys generate --usage reviewer --out /secure/hermes/reviewer.pem
```

将命令输出的公钥写入相应用途的 trust store。先加入新 active key，再重新签名活动
manifest/执行一次 `validate-config`，最后撤销旧 key。Publisher 被撤销时，所有活动角色
manifest 必须由新的 Publisher 重新签名；不得仅修改 trust store 继续使用旧 manifest。

撤销记录必须设置 `status: revoked` 和 `revoked_at`。新签名不接受已撤销 key；历史签名仅在
签署时间严格早于 `revoked_at` 时可用于审计验证。`disabled` key 在任何时间都不接受。

## 构建角色镜像和 manifest

```bash
python scripts/build_role_image.py validate
python scripts/build_role_image.py build \
  --base-image python:3.11-slim@sha256:<reviewed-digest> \

docker image inspect --format '{{index .RepoDigests 0}}' hermes-role-runtime:phase2
python scripts/build_role_image.py manifest \
  --image <repository>@sha256:<repo-digest> \
  --key-id publisher-2026-01 \
  --private-key /secure/hermes/publisher.pem \
  --output config/role-manifests.json
```

## 本地验收顺序

1. 以随机 loopback 端口启动 `tests/e2e_lab`，把端口写入 local-lab scope。
2. `hermes-security validate-config --config ... --scope ...`；该命令不得连接靶场。
3. `hermes-security doctor --config ...`，确认 Hermes Agent 0.16.0、ACP v1、Docker daemon、
   prompt/manifest 签名与三类 key 分离。
4. `run` 应以退出码 20 停在 `awaiting_approval`，此时只存在一份 Recon HTTP 证据。
5. `approve` 后第一次 `resume` 应以退出码 21 停在 `awaiting_review`，总 HTTP 请求数为 3。
6. Reviewer 签署 accepted 后第二次 `resume` 才能生成正式报告并返回 0。
7. 另跑 reject 路径；它必须返回 22，不运行 Verifier、不生成 finding。
8. 检查六个 handoff 分别来自独立容器/PID/ACP session，验收链路中不得出现
   `FixtureAgentRunner` 或测试 `popen_factory`。

可使用一键驱动执行 accepted 与 reject 两条链路；私钥只存在临时目录，运行产物和日志写入
指定 artifact root，容器按 `com.hermes.*` 标签在 `finally` 中清理：

```bash
python scripts/run_phase2_e2e.py \
  --hermes-cli /path/to/hermes \
  --hermes-python /path/to/hermes-python \
  --model deepseek-v4-flash \
  --artifact-root /secure/hermes-e2e-artifacts
```

角色或验证失败时，当前 run 进入 `failed` 并写入脱敏 `failure.json`。不得在原 run 中重置
请求预算或复用 ApprovalBundle；使用 `hermes-security retry --config ... --run-id ...` 创建带
`plan/retry-lineage.json` 的新 run，重新形成 Candidate 并重新审批。
