# Hermes 硬护栏行为规范（`hooks/guardrail.py`）

> 状态：规范性（登记确定性护栏的判定规则）
> 关系：落实 `docs/04` §2 指出的「不能用可被 prompt-injection 绕过的 LLM 当硬边界」修复；
> 补齐 `docs/08`（PRD）§5 仅一句「hook 仅是外围辅助」的欠记录。
> 验收：`tests/test_guardrail_hook.py`（7 例，含越界 deny 回归）。

## 1. 定位与边界

`hooks/guardrail.py` 是一个 **Claude Code PreToolUse hook**：在宿主运行时**每次 `Bash` 调用之前**
确定性地（不经 LLM）判定 allow / ask / deny。它是**外围纵深防御**，**不是**主包的安全边界——
主包真正的强制点是父运行时 Gateway（PRD §5.1）。护栏的价值在于：即使编排层/模型被诱导发出越界
命令，宿主层仍能在命令执行前 fail-closed。

**设计原则**：宁可误报（fail-closed）也不放行越界；无法判定目标时，若命令明显触网 → ask。

## 2. 输入 / 输出契约

- **输入**：stdin 传入 PreToolUse JSON，含 `tool_name` 与 `tool_input`（`Bash` 的 `command`）。
- **输出**：stdout 打印 `hookSpecificOutput.permissionDecision ∈ {allow, ask, deny}` 及 `permissionDecisionReason`；`exit 0`。
- **非命令类工具**（`tool_name` 非 `Bash`/`BashOutput`）直接 allow。
- **无法解析输入** → ask（保守）。

## 3. 判定顺序与规则

判定按以下顺序短路，命中即返回：

### 3.1 危险命令 → **deny**（`DENY_PATTERNS`）
系统破坏 / DoS / 反弹 shell / 持久化 / 外泄，例如：

| 类别 | 模式（节选） |
|---|---|
| 删根/擦盘 | `rm -rf /`（放行 `/tmp`、`/scratch`）、`mkfs`、`dd if=… of=/dev/…`、`> /dev/sd[a-z]` |
| 关机 | `shutdown`、`reboot` |
| fork bomb | `:(){ :|:& };:` |
| 反弹 shell | `bash -i >& /dev/tcp/…`、`nc -e`、`/dev/tcp/<ip>` |
| 持久化 | `authorized_keys` |
| DoS 压测 | `hping3 --flood`、`slowloris`、`slowhttptest`、`ab -n <大数>`、`--flood`、`-t0` |

### 3.2 scope 越界 → **deny / ask**（读 `scope.yaml`）
从命令抽取候选网络目标（主机名/IP/URL 主机部分），逐个判定：

- 目标是本地回环（`localhost`/`127.0.0.1`/`::1`/loopback）：`allow_localhost` 为真则放行，否则 deny；
- 命中 `out_of_scope` → deny（铁律 #1）；
- `in_scope` 为空（无法确认授权）→ ask；
- 不匹配 `in_scope` → deny（越界拒绝）。

**scope schema（两种，向后兼容）**：
1. 当前 `scope.yaml`：`rules: [{host, schemes, ports, allow_private, …}]` —— 护栏从 `rules[].host` 推导 `in_scope`；
2. 旧显式列表：`in_scope` / `out_of_scope` / `allow_localhost`。

> 归一化由 `resolve_scope()` 完成。**2026-08-01 修复**：此前护栏只认 schema 2，对当前 `scope.yaml`
> 的 `rules` schema 一律读到空 `in_scope` → 所有非本地目标降级为 ask，无法据真实 RoE 精确 deny。
> 修复后可对 `rules` 外的主机精确 deny（见回归 `test_out_of_scope_host_is_denied_via_rules_schema`）。

### 3.3 dry-run 下触网 → **ask**
`scope.dry_run`（缺省取环境 `HERMES_DRY_RUN`，默认 on）为真时，任何触网命令
（有目标，或命中 `curl|wget|nmap|nuclei|httpx|subfinder|amass|ffuf|nikto`）→ ask（铁律 #5）。

### 3.4 状态改变 / 利用 / 高噪声 → **ask**（`ASK_PATTERNS`，HITL）
`sqlmap`、`hydra`、`medusa`、`patator`、`msfconsole`/`msfvenom`/`metasploit`、`masscan`、
`-X (POST|PUT|DELETE|PATCH)`、`--method (POST|PUT|DELETE|PATCH)`、高速率 `nuclei -rl <大数>`。

### 3.5 其余 → **allow**（scope 内、非危险）

## 4. 启用方式

护栏**默认未启用**，需手动合并 `hooks/settings.snippet.json` 进项目或用户级 `.claude/settings.json`：

```json
{
  "hooks": { "PreToolUse": [ { "matcher": "Bash",
    "hooks": [ { "type": "command",
      "command": "/Volumes/Samsung/TapBug/Hermes-安全检查团队/.venv/bin/python /Volumes/Samsung/TapBug/Hermes-安全检查团队/hooks/guardrail.py" } ] } ] }
}
```

解释器用项目 `.venv`（含 `pyyaml`，可读 `scope.yaml`）。护栏仅依赖 stdlib + `pyyaml`；缺 `pyyaml`
时优雅降级为空 scope（此时非本地目标走 §3.2 的 ask 分支）。scope 路径可用 `HERMES_SCOPE` 覆盖。

## 5. 验证

`tests/test_guardrail_hook.py` 以真实子进程驱动护栏，覆盖：危险命令 deny、反弹 shell deny、
**基于 `rules` schema 的越界 deny（回归）**、dry-run 触网 ask、状态改变 ask、良性本地 allow、
非 `Bash` 工具 allow。

## 6. 已知局限（诚实边界）

- 目标抽取是**正则启发式**，可能误报/漏报畸形命令里的主机；护栏据此偏保守（fail-closed）。
- 护栏**不替代** Gateway：真正的 scope/审批/预算强制在父运行时（PRD §5.1）。护栏是宿主层兜底。
- 它只检查 `Bash` 命令文本，不理解管道语义或环境变量展开后的真实目标。
