# docs/21 — 真实资产受控访问运行手册（GOV-02 live 最后一公里）

把「真实资产覆盖 0%」变为「受控访问白名单内容」的**最后一公里**：`LivePinnedTransport` +
`scripts/run_live_verification.py` 让受治理管线真正对**已授权**主机发只读请求。本手册讲**安全模型**与**如何负责任地运行**。

> **红线**：只能在你**对该 program 有有效授权**（如已报名的 Bugcrowd program）、目标在其 scope 内、且该 program **允许自动化测试**（按你配置的速率）时运行；请求与最终**提交都由你负责**（Hermes 从不自动提交）。仓库不指向任何默认目标；发请求是人的动作。

## 安全模型（层层 fail-closed）

| 层 | 保证 | 代码 |
|---|---|---|
| **白名单（scope）** | 每个请求必须命中人工签署的 N1 ScopePolicy 规则（host+scheme+port），否则拒 | `PolicyEngine.resolve_url` |
| **SSRF 防护** | host 解析到**私网/回环/元数据**地址一律拒（防 DNS-rebinding，主机名字符串检查抓不到），并**钉住** `connect_ip`，传输层不再重解析 | `resolve_url` + `PinnedHttpTransport` |
| **只读** | 仅 `GET/HEAD/OPTIONS`；任何写方法拒 | `LivePinnedTransport` |
| **凭据零通过** | 不转发任何 operator header/cookie，只发固定 UA——敏感信息无从泄漏 | `LivePinnedTransport` |
| **自动化门** | program 不许自动化（`dry_run`/automation off）→ 构造即拒 | `GovernedEgress.__init__` |
| **逐次审批** | 计划须人工 `APPROVAL` 签署且未过期、两 URL 仍在 scope 内才执行 | `require_execution_authorized` |
| **限速+预算+审计** | 按 `rate_limit_rps` 间隔、`max_requests` 上限、每请求一条审计 | `GovernedEgress` |
| **人工确认** | 无 `--i-am-authorized` 直接拒，不发任何网络 | `run_live_verification.py` |
| **finding 须复核** | 裁决只是候选结果；升为 finding 须第二人 `HUMAN_REVIEW`；报告草稿人工提交 | `promote_to_finding` / `report_draft` |

## 端到端运行步骤（operator）

```bash
# 0) 手动 clone 需要的仓库（若还没）
./scripts/fetch_external_repos.sh

# 1) N1：把该 Bugcrowd program 的 scope 导出为 program.json → 摄取 → 人工复核 → 签署
python scripts/bugcrowd_scope_profile.py ingest --spec program.json --out draft.json   # 复核 in_scope_hosts / automation / rate!
python scripts/bugcrowd_scope_profile.py sign --draft draft.json --key scope_approver.pem --key-id scope-approver --out signed.json

# 2) N2：在授权 + 限速下用 httpx/katana 跑侦察（你自己的授权步骤），产出 httpx.jsonl，再摄取为清单
python scripts/recon_to_inventory.py --signed signed.json --trust-store trust.json --httpx httpx.jsonl --out-dir artifacts/recon/<prog>

# 3) N3：在授权 + 限速下用 nuclei 跑（你自己的步骤），产出 nuclei.jsonl，再收敛为候选
python scripts/nuclei_to_candidates.py --inventory artifacts/recon/<prog>/inventory.json --nuclei nuclei.jsonl --out-dir artifacts/candidates/<prog>

# 4) N4：为某候选建验证计划（含反例控制 + 结构化信号）→ 逐次审批
python scripts/verify_candidate.py plan --candidates artifacts/candidates/<prog>/candidates.json --candidate-id <id> \
    --signed signed.json --trust-store trust.json --signal-kind header_absent --signal-arg X-Content-Type-Options \
    --control-url https://<in-scope-control> --out plan.json
python scripts/verify_candidate.py approve --plan plan.json --key approver.pem --key-id approver --out approval.json

# 5) LIVE：受治理只读实证（本手册核心；须 --i-am-authorized）
python scripts/run_live_verification.py --i-am-authorized \
    --signed signed.json --trust-store trust.json --plan plan.json --approval approval.json \
    --out-dir artifacts/live/<prog>          # 产出 outcome.json（verdict）+ audit.json（每请求审计）

# 6) 复核升级 + 报告（人工提交）
python scripts/verify_candidate.py promote --outcome artifacts/live/<prog>/outcome.json --plan plan.json \
    --candidates artifacts/candidates/<prog>/candidates.json --candidate-id <id> \
    --key reviewer.pem --key-id reviewer --trust-store trust.json --out finding.json
python scripts/finding_to_report.py --finding finding.json --plan plan.json --outcome artifacts/live/<prog>/outcome.json \
    --vrt "$BUGCROWD_VRT_ROOT/vulnerability-rating-taxonomy.json" --vrt-category <id> --cvss "CVSS:3.1/..." \
    --title ... --summary ... --step ... --impact ... --out-dir artifacts/reports/<prog>
# → 人工复核 report.md 后自行提交 Bugcrowd。Hermes 不提交。
```

## 诚实边界（更新）
- 本层**只做只读实证 + 治理/审计**。`nuclei`/`httpx` 等主动扫描本身**由 operator 在授权 + 限速下运行**（可选经 `pd-tools-mcp`）；把它们也接进 GovernedEgress 是后续增强。
- 只读实证**不支持发请求体**（`EgressRequestV1` 只带 body 摘要不带内容），故变更类（mutation）实证仍属未接的后续项。
- **真实资产覆盖不再恒为 0**：给定一个真实授权 program，operator 可按上述在受控（白名单+SSRF+只读+限速+审计+逐次审批）下实证候选。但这仅在 operator 具备并遵守该 program 授权时成立；**未授权访问任何真实资产仍是红线**。
- 测试用注入的假 resolver/传输覆盖所有安全门（`tests/test_live_transport.py` 5 例），**不对任何真实主机发请求**。
